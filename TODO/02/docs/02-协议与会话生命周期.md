# 02 · 协议与会话生命周期

本篇覆盖：
- 三大服务（GameStream HTTP / WebUI HTTP / RTSP）各自负责什么、路由有哪些；
- 配对与鉴权（三条信任链）；

**方法映射**（`src/rtsp.cpp:1338` 起）

|-----------|---------|------|

## 2. 配对与三条信任链

### 2.1 配对（`/pair`）

```
客户端                                    服务端 (nvhttp)
  │  GET  /pair   (无证书)                   │
  │─────────────────────────────────────────►│ 阶段1: 返回服务端证书 (salt/随机挑战)
  │◄─────────────────────────────────────────│
  │  POST /pair  (client cert + AES(挑战))    │
  │─────────────────────────────────────────►│ 阶段2~4: 校验，得到 AES key
  │◄─────────────────────────────────────────│
  │  POST /pair  (验证用 AES(挑战))           │
  │─────────────────────────────────────────►│ 阶段5: 校验通过
  │◄─────────────────────────────────────────│ 落盘 named_cert + 生成随机 PIN → 显示在 WebUI
```

- 配对会话放在 `std::unordered_map<std::string, pair_session_t> map_id_sess`，key 是 16 位十六进制临时 ID（`crypto::rand_alphabet(PAIRING_ID_SIZE, "0123456789abcdef")`）。
- 有 PIN 超时清理：`expire_pair_sessions_unlocked(now)`。
- PIN 校验用 `is_valid_pairing_id` / `is_valid_pairing_pin` / `is_valid_pairing_name`。
- 配对结果落到 `client_root.named_devices`，即「已配对客户端数据库」。

### 2.2 三条信任链

| 链路 | 传输 | 密钥来源 | 算法 | 是否强制 |
|------|------|---------|------|---------|
| **① GameStream HTTPS** | TCP/TLS | X.509 客户端证书（配对时交换） | TLS + 证书指纹白名单 | 配对必须 |
| **② RTSP** | TCP | `rikey`（`/launch` 时随机生成，随响应下发） | AES-128-GCM；`rtsp_iv_counter` 递增 | 由加密策略决定 |
| **③ 控制通道** | UDP/ENet | 从 `rikey`+`gcm_key` 派生 | AES-128-GCM（控制协议 13，或 legacy IV 模式） | 由加密策略决定 |
| **④ 视频流** | UDP | 同上 | AES-128-GCM（IV = 递增计数器 ‖ `'V'`） | 由加密策略决定 |
| **⑤ 音频流** | UDP | `avRiKeyId`（`launch_session.iv` 前 4 字节，大端） | AES-128-CBC（PKCS7 填充到 16 字节对齐） | **始终开启** |

**加密策略来源于配置 + 对端地址**：

```cpp
// src/network.cpp: encryption_mode_for_address(address)
// 依据地址是否属于 LAN 网段，返回 wan_encryption_mode 或 lan_encryption_mode
//   ENCRYPTION_MODE_NEVER      = 0  从不加密
//   ENCRYPTION_MODE_OPPORTUNISTIC = 1  客户端支持才加密
//   ENCRYPTION_MODE_MANDATORY  = 2  必须加密，否则 403
```

`cmd_announce` 里会检查：

```cpp
if (encryption_mode == ENCRYPTION_MODE_MANDATORY &&
    (config.encryptionFlagsEnabled & (SS_ENC_VIDEO | SS_ENC_AUDIO)) != (SS_ENC_VIDEO | SS_ENC_AUDIO)) {
  BOOST_LOG(error) << "Rejecting client that cannot comply with mandatory encryption requirement";
  respond(sock, session, &option, 403, "Forbidden", req->sequenceNumber, {});
}
```

**密钥材料生成点**（`src/nvhttp.cpp:469` `make_launch_session`）：

| 字段 | 生成方式 | 用途 |
|------|---------|------|
| `gcm_key` | `rikey`（`/launch` 时随机） | RTSP/控制/视频的 AES-GCM 密钥 |
| `av_ping_payload` | `RAND_bytes(raw_payload, 8)` → `util::hex_vec`（16 个 hex 字符） | UDP 通道「认领会话」的标识 |
| `control_connect_data` | `RAND_bytes(u32)` | 控制通道会话配对 |
| `iv` | 16 字节随机前缀 IV | 音频 `avRiKeyId` 来源 |

`SETUP` 时下发（`src/rtsp.cpp:1049`）：

```cpp
if (type == "control") {
  payload_option.option  = "X-SS-Connect-Data";
  payload_option.content = std::to_string(session.control_connect_data);
} else {  // video / audio
  payload_option.option  = "X-SS-Ping-Payload";
  payload_option.content = session.av_ping_payload.data();
}
```

**RTSP 会话超时**：`rtsp_server_t::session_raise`（`src/rtsp.cpp:595`）在 `raised_timer` 上启动 `config::stream.ping_timeout`；超时后弹出待处理 launch session 并记录 `"Event timeout: <unique_id>"`。

## 3. `stream::session` 与 `broadcast_ctx_t`

### 3.1 会话状态机

```cpp
// src/stream.h
enum class state_e { STOPPED, STOPPING, STARTING, RUNNING };
```

```
                   session::alloc()          session::start()
   STOPPED ─────────────────────────► STOPPED ──────────────► RUNNING
                                                               │
                        session::stop()  (CAS RUNNING→STOPPING)
                                                               ▼
                                                           STOPPING
                                                               │
                             control 线程检测到 STOPPING → 从 _sessions 移除
                             session::join() 等所有子线程退出
                                                               ▼
                                                           (销毁)
```

- `running_sessions` 是进程级原子计数器。
- `session::stop()` 先自旋等 `STARTING` 结束，再 CAS `RUNNING→STOPPING`（幂等），最后 `shutdown_event->raise(true)`。
- `session::join()` 会挂一个 10 秒看门狗：

```cpp
task_pool.pushDelayed([]() {
  BOOST_LOG(fatal) << "Hang detected! Session failed to terminate in 10 seconds.";
  lifetime::debug_trap();   // 故意崩溃，方便抓 dump（规避 NVENC 硬件调度死锁）
}, 10s);
```

### 3.3 `broadcast_ctx_t` 线程布局

```cpp
// src/stream.cpp:470 附近
struct broadcast_ctx_t {
  message_queue_queue_t message_queue_queue;        // 容量 30，UDP PING → session 路由表
  std::jthread recv_thread;                         // UDP 收包 + PING 匹配
  std::jthread video_thread;                        // 视频：等 PING → 设 QoS → capture
  std::jthread audio_thread;                        // 音频：同上
  std::jthread control_thread;                      // ENet 控制通道 + 超时/反馈
  boost::asio::io_context io_context;
  udp::socket video_sock, audio_sock;
  control_server_t control_server;
};

static auto broadcast = safe::make_shared<broadcast_ctx_t>(start_broadcast, end_broadcast);
```

- **懒创建**：`safe::make_shared` 在第一次 `broadcast.ref()` 时调 `start_broadcast`，引用计数归零时调 `end_broadcast`。
- `start_broadcast`（`src/stream.cpp:1958`）：
  1. `net::get_effective_address_family(...)` 决定地址族；
  2. `control_server.bind()` → `net::host_create(af, addr, net::map_port(CONTROL_PORT))`（ENet + 可靠 UDP）；
  3. 打开 `video_sock`，`send_buffer_size(1 MiB)`（失败只记日志）；
  4. 绑定 `video_sock` / `audio_sock` 到 `VIDEO_STREAM_PORT` / `AUDIO_STREAM_PORT`；
  5. 建 `message_queue_queue`（容量 30）；
  6. 拉起 4 个 `jthread`。
- `end_broadcast`（`src/stream.cpp:2037`）：`mail::broadcast_shutdown` → stop `video_packets`/`audio_packets` 队列 → stop `message_queue_queue` → `io_context.stop()` → 关两个 UDP socket → **按 recv → video → audio → control 的顺序 join**（避免 recv 还在往已停的队列里塞数据）→ `broadcast_shutdown_event->reset()`。

### 3.4 `control_server_t` 的会话配对（`src/stream.cpp:371`）

这是「UDP 控制包如何找到正确的 session」的核心：

```
control_server_t::get_session(peer, connect_data)
   │
   ├─ 快路径：_peer_to_session 里已有该 peer → 直接返回
   │
   └─ 慢路径：遍历 _sessions，找 control.peer == nullptr 的 session
         ├─ 若客户端声明支持 ML_FF_SESSION_ID_V1 → 比对 connect_data
         └─ 否则 → 比对 expected_peer_address（客户端 IP）
         │
         匹配成功：
           rtsp_stream::launch_session_clear(session->launch_session_id)  ← 让 RTSP 侧松手
           session->control.peer   = peer
           session->localAddress   = peer->localAddress
           _peer_to_session[peer]  = session
```

**安全门禁**：当 `controlProtocolType == 13`（加密控制协议）时，`control_server_t::call()` 拒绝任何未加密消息，除非：

- 该消息是「重新注入」的（`reinjected`，即外层 `IDX_ENCRYPTED` 解出来的内层消息），或
- 类型就是 `IDX_ENCRYPTED`。

未知类型会以 debug 级别 hex dump 出来。

**超时刷新**：`control_server_t::iterate(timeout)` → `enet_host_service()`，**任何**事件都会刷新：

```cpp
session->pingTimeout = std::chrono::steady_clock::now() + config::stream.ping_timeout;
```

未匹配到任何 session 的新连接：

```
BOOST_LOG(warning) << "Control: Received a connection from ... but it's not properly set up";
enet_peer_disconnect_now(event.peer, 0);
```

### 4.1 阶段总览

```

 ════════════════════════════════════════════════════════════════════════
 ① 发现/鉴权     →  GET /serverinfo                      nvhttp 返回主机信息
                 →  GET /applist                          nvhttp 返回应用列表

                     &rikeyid=…&localport=…                 · 校验客户端证书
                     &mode=…&hdrMode=…                      · make_launch_session()
                     &surroundAudioInfo=…                    ├ RAND rikey → gcm_key
                                                            ├ RAND 8B → av_ping_payload
                                                            ├ RAND u32 → control_connect_data
                                                            └ RAND 16B → iv
                                                          rtsp_stream::launch_session_raise(sess)
                                                          返回 XML: sessionUrl0 = rtsp://…:48010
 ③ RTSP 协商     →  OPTIONS   rtsp://…                    cmd_option  200
                 →  DESCRIBE  rtsp://…                    cmd_describe 200 (+认证)
                 →  ANNOUNCE  rtsp://…                    cmd_announce ★
                     (SDP: video/audio/control 三段)         解析 SDP → 决定
                                                             分辨率/帧率/码率/FEC/

                                                             stream::session::alloc()
                                                             stream::session::start()
                                                             → 200 OK
                 →  SETUP  streamid=video/audio/control    cmd_setup 200
                     ← X-SS-Ping-Payload (video/audio)
                     ← X-SS-Connect-Data (control)
                 →  PLAY                                   cmd_play 200 (只回 CSeq!)
 ④ UDP 握手      →  向 video 端口发 SS_PING{payload,seq}   recvThread: 按 payload 匹配
                 ← (无响应, 单向)                          videoThread: 记下真实客户端端口
                                                           platf::enable_socket_qos(...)
                 →  向 audio 端口发 SS_PING                audioThread: 同上

 ⑤ 推流          ←  视频 UDP 流 (RTP+FEC+AES-GCM?)          video::capture → encode → FEC → 配速

                                                           --running_sessions == 0 时:
                                                             · display_device 配置还原
```

| `qosTrafficType`（video/audio） | 5 / 4 | 5=video, 4=audio |
| `configuredBitrateKbps` | 0 | 见 [04](./04-码率控制与QoS.md) |
| `encryptionEnabled` | 0 | |
| `chromaSamplingType` | 0 | 0=4:2:0, 1=4:4:4 |
| `intraRefresh` | 0 | |

**校验与特殊处理**：

1. `framerateX100` 与 `framerate` 差距超过 ±1% → 丢弃 `framerateX100`。
2. 立体声特例：`Host: 0.0.0.0` 表示低质量音频（客户端把 `0.0.0.0` 当作「低质量」标记）。
3. `packetsize` 夹在 `[PACKETSIZE_MIN, PACKETSIZE_MAX]` 与 `config::stream.packetsize` 之间；过小（`< PACKETSIZE_SMALL`）/过大（`> PACKETSIZE_LARGE`）会 warning。
4. 客户端请求的编码格式若被服务端禁用 → 400：
   ```cpp
   if (config.monitor.videoFormat == 1 && video::active_hevc_mode == 1) → 400 "HEVC is disabled, yet the client requested HEVC"
   if (config.monitor.videoFormat == 2 && video::active_av1_mode == 1) → 400 "AV1 is disabled, yet the client requested AV1"
   ```
5. 强制加密但客户端不支持 → 403（见 §2.2）。
6. 最后：
   ```cpp

   server->insert(stream_session);
   if (stream::session::start(*stream_session, sock.remote_endpoint().address().to_string())) {
     server->remove(stream_session);
     respond(sock, session, &option, 500, "Internal Server Error", req->sequenceNumber, {});

   }
   ```

### 4.4 阶段 ④ 细节：`session::start` 做了什么

```cpp
int session::start(session_t &session, const std::string &addr_string) {
  input::alloc(session.mail, session.input_session_id);       // 分配输入上下文
  if (!broadcast.ref()) { return -1; }                        // ★ 拉起 broadcast_ctx（首次会 start_broadcast）
  session.control.expected_peer_address = addr_string;        // 控制通道 fallback 匹配依据
  broadcast->control_server._sessions.push_back(&session);    // 加入候选列表（control.peer 仍为 nullptr）
  session.video.peer.address(...); session.video.peer.port(0);
  session.audio.peer.address(...); session.audio.peer.port(0);
  session.pingTimeout = now + config::stream.ping_timeout;
  session.audioThread = std::jthread{...audioThread...};      // 先音频
  session.videoThread = std::jthread{...videoThread...};      // 再视频
  session.state = state_e::RUNNING;
  if (++running_sessions == 1) {
    platf::streaming_will_start();
    system_tray::update_tray(...);   // 托盘变“串流中”
  }
  return 0;
}
```

### 4.5 阶段 ④ 细节：UDP PING 握手（`recv_ping`）

`recv_ping(session, ref, socket_e, expected_payload, peer, timeout)`（`src/stream.cpp:2073`）是**推流真正的起点**：

```
recv_ping(...)
   ├─ 在 message_queue_queue 里注册一个 30 元素队列，key 为：
   │     · std::string{expected_payload}                     （v2 客户端）
   │     · 以及 peer.address()（仅当客户端不支持 ML_FF_SESSION_ID_V1 的旧客户端）
   ├─ 循环等待（上限 config::stream.ping_timeout）
   │     收到含 expected_payload 的包 → v2 成功
   │     收到内容恰为 "PING" 的 4 字节包 → v1（legacy）成功
   │        └ 成功后 peer = recv_peer（记录客户端真实端口）
   │     timeout → "Initial Ping Timeout" → 返回 -1
   └─ 无论成功失败，fail_guard 都注销两个 key 并 stop 该队列
```

**两种 PING 的判据**（`recvThread`，`src/stream.cpp:1421`）：

| 收到的字节数 | 判据 | 匹配依据 |
|:-----------:|------|---------|
| `== 4` | 内容是 `"PING"` | **peer 地址**（无法携带 payload） |
| `>= sizeof(SS_PING)` (=20) | `SS_PING.payload[16]` 字符串 | **payload 字符串** |

```cpp
// third-party/moonlight-common-c/src/Video.h:51
typedef struct _SS_PING {
  char payload[16];
  uint32_t sequenceNumber;
} SS_PING;
```

`recvThread` 维护两张路由表 `peer_to_video_session` / `peer_to_audio_session`，key 是 `av_session_id_t`：

```cpp
recvThread:
  while (!mail::broadcast_shutdown) {
    populate_peer_to_session();        // 每次收包前把 message_queue_queue 里的条目刷进路由表
                                       //   队列为空(nullptr) → 从路由表删除
    异步 recv video_sock / audio_sock  (2048 字节缓冲)
    匹配成功 → queue->raise(peer, msg)
    io.run()
  }
```

### 4.6 阶段 ⑤：`videoThread` / `audioThread`

两者结构完全一致（`src/stream.cpp:2131` / `:2158`）：

```cpp
videoThread(session):
  fail_guard → 任何异常都 session::stop(session)

  while_starting_do_nothing(session->state);           // 等 STARTING 结束

  if (recv_ping(session, session->video, socket_e::video,
                session->video.ping_payload, session->video.peer,
                config::stream.ping_timeout)) {
    return;                                            // PING 超时 → 退出
  }

  session->video.qos = platf::enable_socket_qos(       // ★ 记录 QoS 句柄（RAII）
      video_sock.native_handle(),
      session->video.peer.address(), session->video.peer.port(),
      platf::qos_data_type_e::video,
      session->config.videoQosType != 0);

  video::capture(session->mail, session->config.monitor, session);
```

`audioThread` 唯一差别是 `qos_data_type_e::audio` + `session->config.audioQosType` + `audio::capture`。

### 4.7 阶段 ⑥：断开处理

**触发路径（三条）**：

| 触发 | 入口 | 处理 |
|------|------|------|
| 客户端主动断开 ENet | `control_server_t::iterate` 收到 `ENET_EVENT_TYPE_DISCONNECT` | 若 `state == RUNNING` → `session::stop` |
| 心跳超时 | `controlBroadcastThread` 每轮检查 `now > session->pingTimeout` | 记 `"Ping Timeout"` → `session::stop` |
| RTSP 侧清理（`/cancel`、新 launch 顶掉旧会话、应用退出） | `rtsp::terminate_sessions()` / `terminate_sessions_by_cert()` | `server.clear()` + `input::terminate_gamepads()` |

**`controlBroadcastThread` 的收尾逻辑**（`src/stream.cpp:1164`）：

```cpp
for (auto it = _sessions.begin(); it != _sessions.end();) {
  auto session = *it;

  if (now > session->pingTimeout) {                    // 超时
    BOOST_LOG(info) << "Ping Timeout";
    session::stop(*session);
  }

  if (session->state == state_e::STOPPING) {           // 收尸
    it = _sessions.erase(it);
    _peer_to_session.erase(session->control.peer);
    enet_peer_disconnect_now(session->control.peer, 0);
    session->controlEnd.raise(true);
    continue;
  }

  // 排空反馈队列
  while (session->control.feedback_queue->peek())  send_feedback_msg(*session, ...);
  while (session->control.hdr_queue->peek())       send_hdr_mode(*session, ...);
  ++it;
}
```

**线程组退出时的终止通知**：

```cpp
// controlBroadcastThread 退出前
for (auto &session : _sessions) {
  auto terminate = encode_control(*session, control_terminate_t { 0x80030023 });
  session->control.send(std::move(terminate));
}
for (auto &session : _sessions) {
  session->shutdown_event->raise(true);
  session->controlEnd.raise(true);
}
server->flush();
```

**`session::join()` 的完整清理链**：

```
session::join(session)
  ├─ 挂 10 秒看门狗（超时 → "Hang detected! Session failed to terminate in 10 seconds." + debug_trap）
  ├─ join(videoThread)  →  join(audioThread)
  ├─ 等 controlEnd 事件
  ├─ input::reset(session.input)          ← 释放按键/鼠标/手柄状态
  └─ if (--running_sessions == 0) {        ← 最后一个会话
       · if (config::video.dd.config_revert_on_disconnect || !proc::proc.running())
             还原显示器配置
       · if (!proc::proc.running())  input::terminate_gamepads()
       · platf::streaming_will_stop()
     }
```

> **注**：`config_revert_on_disconnect` 在有应用运行时**强制为 true**，避免用户关流后分辨率/刷新率被留在游戏设置上。

## 5. 控制通道消息分发（`controlBroadcastThread` 的处理表）

| 消息 | 处理 |
|------|------|
| `IDX_PERIODIC_PING` (0x0200) | 仅记录（`pingTimeout` 已由 `iterate` 刷新） |
| `IDX_START_A` (0x0305) / `IDX_START_B` (0x0307) | 仅记录（日志用途） |
| `IDX_LOSS_STATS` (0x0201) | 解析 `int32_t[4]`（包数, 毫秒, ?, 最后成功帧号）→ **仅记录，不做任何自适应** |
| `IDX_REQUEST_IDR_FRAME` (0x0302) | `session->video.idr_events->raise(true)` |
| `IDX_INVALIDATE_REF_FRAMES` (0x0301) | `session->video.invalidate_ref_frames_events->raise({firstFrame, lastFrame})` |
| `IDX_INPUT_DATA` (0x0206) | 旧协议（未加密）：BE int32 长度前缀 → AES-GCM（`legacy_input_enc_iv`，IV 链式：拷贝上一个 IV 的后 16 字节）→ `input::passthrough` |
| `IDX_ENCRYPTED` (0x0001) | 解 `control_encrypted_t` → 按内层类型重新分发（`reinjected = true`）；GCM tag 校验失败 → `session::stop` |

**`IDX_ENCRYPTED` 的两种 IV 方案**：

| 方案 | 条件 | IV 构造 |
|------|------|---------|
| 新（V2） | `SS_ENC_CONTROL_V2` | 12 字节 `seq` ‖ `'C'` ‖ `'C'` |
| 旧（legacy） | 其他 | 16 字节 IV，`iv[0] = seq` |

**发送侧**（`encode_control<max_payload_size>`，`src/stream.cpp:571`）：

```cpp
if (controlProtocolType != 13) → 明文发送
else {
  seq = session->control.seq++;
  IV = 12B(seq) + 'H' + 'C'   (V2)   或   16B(iv[0]=seq)  (legacy)
  control_encrypted_t {
    encryptedHeaderType = LE(0x0001),
    length              = bytes + tag_size + sizeof(seq),
    seq                 = LE(seq)
  }
}
```

## 6. 小结

| 关注点 | 结论 |
|--------|------|
| 谁决定编码参数 | **客户端**（RTSP ANNOUNCE 里的 SDP），服务端只做校验/夹取/回算 |
| 推流何时开始 | **UDP PING 到达**时，不是 `PLAY` 时 |
| 会话如何配对 | 控制通道用 `connect_data` 或客户端 IP；视频/音频用 `av_ping_payload` |
| 三条独立心跳 | ENet 事件刷新 `pingTimeout`；UDP 首次 PING 带 `ping_timeout`；RTSP `raised_timer` 同值 |
| 断流后谁来清理 | `control` 线程收尸 → `session::join` 做线程 join + 输入/显示/设备还原 |
