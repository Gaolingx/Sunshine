# 03 · 输入系统

目标：把客户端（Moonlight）通过**控制通道**送来的输入包，无损地翻译成主机操作系统的原生输入事件（SendInput / uinput / CGEvent），并把主机侧的手柄力反馈、LED、自适应扳机反向送回客户端。

源文件：[src/input.cpp](../../../src/input.cpp)、[src/input.h](../../../src/input.h)、[third-party/moonlight-common-c/src/Input.h](../../../third-party/moonlight-common-c/src/Input.h)

---

## 1. 数据通路总览

```
客户端 Moonlight
   │  ① 构造 NV_*_PACKET（NV_INPUT_HEADER + 载荷）
   │  ② （可选）AES-GCM 加密后包成 IDX_ENCRYPTED(0x0001)
   ▼
ENet 可靠 UDP ──► control_server_t::iterate() ──► controlBroadcastThread
   │                                                   │
   │                                    ┌──────────────┴──────────────┐
   │                                    │ IDX_INPUT_DATA(0x0206)      │ IDX_ENCRYPTED → 解出 0x0206
   │                                    └──────────────┬──────────────┘
   │                                                   ▼
   │                                    input::passthrough(input, std::vector<uint8_t>&&)
   │                                       ① validate_input_packet()   ← 校验失败直接丢弃并记日志
   │                                       ② push 到 input->input_queue（加锁）
   │                                       ③ task_pool.push(passthrough_next_message, input)
   ▼                                                          │
主机的输入注入（L4）                                          ▼
platf::keyboard_update / move_mouse / abs_mouse /      passthrough_next_message()
      button_mouse / scroll / hscroll / unicode /        ① 取出队首
      touch_update / pen_update / gamepad_update /       ② 尝试批处理（batch()）
      gamepad_touch / gamepad_motion /                      · 只有“相对鼠标移动”可批
      gamepad_battery / alloc_gamepad                        · 用 __builtin_add_overflow 检查 16 位累加溢出
                                                         ③ 释放锁（此后不再持有 input_queue_lock）
                                                         ④ input::print(payload)  ← 调试日志
                                                         ⑤ 按 magic 分发

反向：主机手柄力反馈
platf::alloc_gamepad(..., feedback_queue)  ──►  feedback_queue（每会话）
   ▼
controlBroadcastThread: send_feedback_msg()
   ├ control_rumble_t            0x010b  ← LI_RUMBLE
   ├ control_rumble_triggers_t   0x5500  ← LI_RUMBLE_TRIGGERS
   ├ control_set_motion_event_t  0x5501  ← LI_MOTION
   ├ control_set_rgb_led_t       0x5502  ← LI_RGB_LED

   └ control_set_player_leds_t   0x5504  ← LI_PLAYER_LED
```

## 2. 关键数据结构

### 2.1 内核态寄存器（[src/input.cpp](../../../src/input.cpp) 顶部）

| 名称 | 类型 | 说明 |
|------|------|------|
| `MAX_GAMEPADS` | `min(platf::MAX_GAMEPADS, 16)` | 平台上限与 16 取小 |
| `platf_input` | `platf::input_t*` | 平台输入上下文 |
| `gamepadMask` | 位集 | 已被占用的手柄槽位（`alloc_id` / `free_id`） |
| `key_press` | `std::map<key_press_id_t, bool>` | 当前按下的键（用于断开时统一释放） |
| `mouse_press[5]` | `bool[5]` | 5 个鼠标键状态 |
| `key_press_repeat_id` | `task_id_t` | 当前按键自动重复任务 |
| `WHEEL_DELTA` | 120（回退值） | 滚轮一格 |
| `DISABLE_LEFT_BUTTON_DELAY` | `(task_id_t)0x01` | 特殊值：强制关闭左键延迟 |
| `ENABLE_LEFT_BUTTON_DELAY` | `nullptr` | 特殊值：恢复默认左键延迟 |

**虚拟键码常量**（用于 SHORTCUT 修饰键跟踪）：

| VKEY | 值 | VKEY | 值 |
|------|:--:|------|:--:|
| `SHIFT` | 0x10 | `CONTROL` | 0x11 |
| `LSHIFT` | 0xA0 | `LCONTROL` | 0xA2 |
| `RSHIFT` | 0xA1 | `RCONTROL` | 0xA3 |
| `MENU` (Alt) | 0x12 | `LMENU` | 0xA4 |
| | | `RMENU` | 0xA5 |

**按键标识**：`key_press_id_t = (vk << 8) | flags`，配套 `make_kpid` / `vk_from_kpid` / `flags_from_kpid`。

**浮点坐标**：`netfloat[4]` 是 4 字节小端 IEEE-754，用 `from_netfloat()` / `from_clamped_netfloat()` 解码（触摸/笔坐标）。

### 2.2 `gamepad_t`

```cpp
struct gamepad_t {
  platf::gamepad_state_t gamepad_state;   // 当前状态（含按钮位图、摇杆、扳机）
  task_id_t back_timeout_id;              // BACK 长按 → HOME 的延时任务
  int id { -1 };                          // 全局槽位号，-1 = 未分配
  button_state_e back_button_state { NONE }; // NONE / DOWN / UP
};
```

**`back_button_state` 存在的理由**：当 BACK 被按下足够久（`config::input.back_button_timeout`），Sunshine 会**合成一次 HOME 键**。但客户端的 BACK 此时仍然是「按下」状态，如果不强制把 BACK 固定成一个确定状态，客户端松手时会送一个「BACK 抬起」，导致注入的事件序列与客户端状态**失步**。所以：

- BACK 按下边沿 → `back_button_state = DOWN`（强制 BACK 保持按下，屏蔽后续客户端 BACK 值）
- 调度延时任务：BACK 抬起 → 按 HOME → `sleep(100ms)` → 松 HOME
- BACK 抬起边沿 → 取消延时任务，`back_button_state = UP`

`gamepad_t` 的**析构函数**在 `task_pool.running()` 时通过 `task_pool.push` 释放设备，保证释放发生在任务池线程上（与注入串行）。

### 2.3 `modifier_state_t` 与 `input_t`

```cpp
struct modifier_state_t {
  bool generic_pressed, left_pressed, right_pressed;
  bool any_pressed() const { return generic_pressed || left_pressed || right_pressed; }
};

struct input_t {
  // SHORTCUT 位（客户端按下了 Sunshine 的“组合键修饰”）
  static constexpr uint8_t SHIFT = 0x1, ALT = 0x2, CTRL = 0x4, SHORTCUT = SHIFT|ALT|CTRL;
  uint8_t shortcutFlags { 0 };

  modifier_state_t shift_keys, control_keys, alt_keys;

  std::vector<gamepad_t> gamepads;        // 索引 = client_index（客户端的槽位）
  std::shared_ptr<platf::input_t> client_context;
  safe::mail_t mail;
  safe::event_t<touch_port_t>* touch_port_event;
  safe::queue_t<platf::gamepad_feedback_msg_t>* feedback_queue;

  std::list<std::vector<uint8_t>> input_queue;   // ★ 输入包队列（FIFO）
  std::mutex input_queue_lock;

  task_id_t mouse_left_button_timeout;    // 左键按下延迟任务（避免误触发拖拽）

  touch_port_t touch_port;
  int32_t accumulated_vscroll_delta, accumulated_hscroll_delta;
};
```

### 2.4 「保持输入」（Retained Input）—— 暂停/恢复不丢手柄

```cpp
struct retained_input_map_t {
  // key = 客户端身份（证书或 unique_id），透明哈希以支持异构查找
  unordered_map<..., shared_ptr<input_t>, ..., transparent_hash> map;
  mutex mutex;
};
```

`input::alloc(mail, session_id)` 用 `session_id`（`client_cert` 或 `unique_id`）在保留表里查旧上下文：

- 命中（**恢复串流**）→ `rebind_input(input, mail)`：
  - 把 `touch_port_event` / `feedback_queue` 重新指向**新会话**的邮箱；
  - 对每个手柄调用 `platf::rebind_gamepad(platf_input, {id, client_index}, feedback_queue)`；失败则释放该位。
- 未命中（新客户端）→ 新建 `input_t` 并 `dispatch_input_task()` 注册到 `task_pool`。

这样「暂停 → 恢复」时**虚拟手柄设备不会重建**，很多游戏不会掉手柄。

## 3. 包校验：`validate_input_packet`

所有从网络来的输入包都在进入队列**之前**过这道关（防止畸形包导致越界读）：

```
validate_input_packet(packet, parsed_header)
  ├─ packet.size() >= sizeof(NV_INPUT_HEADER) ?            否则 false
  ├─ declared_size = BE(header.size)
  │    · declared_size >= sizeof(header.magic) ？
  │    · declared_size <= packet.size() - sizeof(header.size) ？
  ├─ switch (LE(header.magic)) {
  │    固定长度类型（如 NV_KEYBOARD_PACKET / NV_SCROLL_PACKET / SS_TOUCH_PACKET …）
  │      → validate_fixed_input_packet<T>(packet, declared_size)
  │           declared_size == sizeof(T) - sizeof(uint32_t)  且  packet.size() >= sizeof(T)
  │    UTF8_TEXT_EVENT_MAGIC
  │      → declared_size - sizeof(header.magic) <= UTF8_TEXT_EVENT_MAX_COUNT
  │    未知 magic → true（放行，交给下游忽略，保持向前兼容）
  │  }
```

失败时的日志：

```
Dropping malformed input packet type [<magic>] with declared payload size [<declared>] and actual size [<actual>]
```

## 4. 分发：`passthrough_next_message` 与批处理

### 4.1 批处理（`batch()`）

客户端会为每个相对鼠标位移单独发一个包，高频鼠标会导致海量小包。批处理把**连续的相对鼠标位移**合并成一个事件：

| 返回 | 含义 |
|------|------|
| `batched` | 已合并，可继续尝试下一个 |
| `not_batchable` | 当前包不能合并，遇到不可合并的**其它类型** → 停止并交回外层 |
| `terminate_batch` | 结束批处理（例如累积和即将溢出） |

溢出检查用 `__builtin_add_overflow`（16 位有符号差值），一旦相加会溢出就停止合并——既防止正向超界，也防止反向：

```cpp
// 只有“相对鼠标移动”是可批的
if (__builtin_add_overflow(sum, delta, &sum)) → terminate_batch
```

### 4.2 magic 分发表

按 `util::endian::little(payload->magic)` 分发（[third-party/moonlight-common-c/src/Input.h](../../../third-party/moonlight-common-c/src/Input.h)）：

| magic 常量 | 值 | 对应处理 |
|-----------|:--:|---------|
| `MOUSE_MOVE_REL_MAGIC_GEN5` | 0x00000007 | `passthrough(PNV_REL_MOUSE_MOVE_PACKET)` — 相对鼠标 |
| `MOUSE_MOVE_ABS_MAGIC` | 0x00000005 | `passthrough(PNV_ABS_MOUSE_MOVE_PACKET)` — 绝对鼠标 |
| `MOUSE_BUTTON_DOWN_EVENT_MAGIC_GEN5` | 0x00000008 | `passthrough(PNV_MOUSE_BUTTON_PACKET)` |
| `MOUSE_BUTTON_UP_EVENT_MAGIC_GEN5` | 0x00000009 | 同上 |
| `SCROLL_MAGIC_GEN5` | 0x0000000A | `passthrough(PNV_SCROLL_PACKET)` |
| `SS_HSCROLL_MAGIC` | 0x55000001 | `passthrough(PSS_HSCROLL_PACKET)` — 横向滚轮 |

## 5. 键盘子系统

### 5.1 修饰键状态跟踪

`update_modifier_state(input, key_code, release)`（[src/input.cpp:960](../../../src/input.cpp) 附近）按 VKEY 更新 `shift_keys` / `control_keys` / `alt_keys` 的 `generic/left/right` 三态。

`update_shortcutFlags(input, keyCode, release)`：

- 按下 → 置位 `input_t::SHIFT/CTRL/ALT`；
- 抬起 → **仅在 `!...any_pressed()` 时清除**。

> **为什么不能直接清？** 因为存在「Right-Alt 被映射成 Meta」这类重映射：按住 Left Alt（→ 置 SHIFT 组合位）时，按下并松开 Right-Alt（会走 Meta 的释放路径），如果无条件清除就会把 Left Alt 的组合状态也清掉。所以必须等所有同族修饰键都抬起。

`is_modifier(keyCode)` 覆盖 `SHIFT/LSHIFT/RSHIFT/CONTROL/LCONTROL/RCONTROL/MENU/LMENU/RMENU`。

### 5.2 注入与组合键

`emit_keyboard_update(key_code, release, flags)`：

```cpp
#ifdef SUNSHINE_TESTS
  if (keyboard_sink()) { /* 单测用的替身 sink，避免真的按键 */ }
#endif
  platf::keyboard_update(platf_input, key_code, release, flags);
```

`send_key_and_modifiers(key_code, release, flags, synthetic_modifiers)`：

1. 按下合成修饰键（`MODIFIER_SHIFT` / `MODIFIER_CTRL` / `MODIFIER_ALT`，由 `SHORTCUT` 位推出）；
2. `emit_keyboard_update(map_keycode(key_code), release, flags)`；
3. 释放合成修饰键。

> 合成修饰键机制让客户端送来的「Ctrl+Shift+F1」这类组合，即使主机侧没有物理按住对应键也能正确表达。

### 5.3 按键自动重复

`repeat_key(key_code, flags, synthetic_modifiers)`：

```cpp
if (key_press 里已找不到该键) {          // 键已抬起
  key_press_repeat_id = nullptr;
  return;                                 // ★ 必须清 id，否则后续按键不会重新排程
}
再发一次按下；
task_pool.pushDelayed(repeat_key, config::input.key_repeat_period, key_code, flags, synthetic);
```

- 首次投递延时由 `config::input.key_repeat_delay`（默认 500 ms）控制；
- 重复周期由 `config::input.key_repeat_period`（默认 `1/24.9 ≈ 40 ms`）控制；
- 客户端送 `KEY_DOWN_EVENT_MAGIC` 且 `keyCode` 命中自动重复设置时才会启动这条链。

### 5.4 断开时释放所有键

`reset_keyboard_keys()` 遍历 `key_press`，对每个按下的键：

```cpp
emit_keyboard_update(map_keycode(vk & 0x00FF), /*release=*/true, flags);
```

> 注意这里把 keyCode **再映射一次**（`map_keycode`）——因为按下时也是映射过的，只有用同样的映射结果去释放才能命中主机侧真正的键。

## 6. 鼠标子系统

| 入口 | 行号 | 要点 |
|------|:----:|------|
| `passthrough(PNV_REL_MOUSE_MOVE_PACKET)` | ~716 | 累加 `deltaX/deltaY`；配合批处理；`config::input.high_resolution_scrolling` 影响滚轮精度 |
| `passthrough(PNV_ABS_MOUSE_MOVE_PACKET)` | ~819 | 绝对坐标 → `platf::abs_mouse(input, touch_port, x, y)` |
| `passthrough(PNV_MOUSE_BUTTON_PACKET)` | ~877 | **左键延迟**：`mouse_left_button_timeout`；`DISABLE_LEFT_BUTTON_DELAY` / `ENABLE_LEFT_BUTTON_DELAY` 特殊 task_id |
| `passthrough(PNV_SCROLL_PACKET)` | ~1220 | 纵向滚轮；`accumulated_vscroll_delta` 累积小步进 |
| `passthrough(PSS_HSCROLL_PACKET)` | ~1243 | 横向滚轮；`accumulated_hscroll_delta` |
| `passthrough(const NV_UNICODE_PACKET *)` | ~1266 | `platf::unicode(input, utf8, size)` |

**左键延迟的意义**：远程点选时，按下瞬间的微小位移常被识别成拖拽。延迟若干毫秒确认「没有位移」后再按下左键，可显著改善点击手感。

**每次调用前都会 `reset_mouse_buttons()`** 清理状态中的鼠标键，避免状态漂移。

## 7. 触摸与笔

`PSS_TOUCH_PACKET` 与 `PSS_PEN_PACKET` 共用 `prepare_absolute_pointer_data()`：

```
prepare_absolute_pointer_data(contactAreaMajor/Mi, contactAreaMinor/Ni, x, y, rotation, …)
  ├─ if (!config::input.mouse) → 忽略
  ├─ client_to_touchport():
  │     from_clamped_netfloat(x) * 65535  →  归一化到 touch_port 的像素坐标
  ├─ monitor_touch_port():
  │     touch_port.width/height 退化(为 0) → "Ignoring touch/pen input due to invalid logical touch dimensions"
  ├─ rotation % 360（除非 LI_ROT_UNKNOWN）
  ├─ scale_client_contact_area()
  └─ platf::touch_input_t / platf::pen_input_t   → platf::touch_update / platf::pen_update
```

触摸点区域的来源是 `session->mail` 上的 `mail::touch_port` 事件，由显示层在分辨率/旋转变化时更新。

## 8. 手柄子系统

### 8.1 槽位分配：`alloc_gamepad`

```
alloc_gamepad(input, client_index, arrival)
  ├─ client_index 越界 → -1
  ├─ 已分配 → 直接返回已有 id
  ├─ id = alloc_id(gamepadMask)                 ← 找第一个空闲位
  ├─ platf::alloc_gamepad(platf_input, {id, client_index}, arrival, input->feedback_queue)
  │     失败 → free_id(gamepadMask, id) → -1
  ├─ gamepad.id = id
  └─ 返回 id
```

`client_index` 是**客户端侧的槽位号**（0..3），`id` 是主机侧的全局槽位。两者分离的好处：客户端 0 号手柄可以映射到主机上任意空闲的虚拟设备。

### 8.2 手柄“到达”事件：`PSS_CONTROLLER_ARRIVAL_PACKET`

```cpp
// 0x55000004
{ uint8_t controllerNumber; uint8_t type; uint16_t capabilities; uint32_t supportedButtonFlags; }
```

构造 `platf::gamepad_arrival_t { type, capabilities, supportedButtonFlags }` → `alloc_gamepad`。
`!config::input.controller` 时整条跳过。

### 8.3 手柄状态：`PNV_MULTI_CONTROLLER_PACKET`

```
passthrough(PNV_MULTI_CONTROLLER_PACKET)
  ├─ !config::input.controller → 跳过
  ├─ controllerNumber 范围检查
  ├─ 若 activeGamepadMask 中该位为 1 且 gamepad.id < 0 → 惰性 alloc_gamepad
  ├─ 若该位为 0 且 gamepad.id >= 0 → free（手柄被拔/关闭）
  ├─ 组装 platf::gamepad_state_t {
  │     buttons = bf | (bf2 << 16),
  │     leftTrigger, rightTrigger,
  │     leftStickX/Y, rightStickX/Y
  │  }
  ├─ back_button_state 强制逻辑（见 §2.2）
  └─ platf::gamepad_update(platf_input, id, state)
```

### 8.4 BACK → HOME 长按

```
BACK 抬起边沿：
   if (config::input.back_button_timeout >= 0ms) {
     back_timeout_id = task_pool.pushDelayed([gamepad]() {
       把 BACK 强制抬起
       platf::gamepad_update(..., HOME 按下)
       sleep(100 ms)
       platf::gamepad_update(..., HOME 抬起)
     }, config::input.back_button_timeout);
   }
BACK 按下边沿：
   取消 back_timeout_id
```

`back_button_timeout` 默认 `-1 ms` = **禁用**（`/config` 里配置）。

### 8.5 手柄其它输入

| 入口 | magic | 处理 |
|------|:-----:|------|
| 触控板 | 0x55000005 | `platf::gamepad_touch` |
| 陀螺仪/加速度计 | 0x55000006 | `platf::gamepad_motion` |
| 电量 | 0x55000007 | `platf::gamepad_battery` |

### 8.6 断开时的清理（注意“保留设备”）

`reset_gamepads(input)`：

1. 取消所有 BACK 超时任务；
2. 对每个手柄 `platf::gamepad_update(..., 全零状态)`；
3. 发送 `LI_TOUCH_EVENT_CANCEL_ALL` 给 `platf::gamepad_touch`（清掉正在进行的触摸）；
4. **不释放虚拟设备**（因为可能是暂停-恢复，设备要留给下一次 `rebind_input`）。

`reset_input_state(input)` = `reset_mouse_buttons()` + `reset_keyboard_keys()` + `reset_gamepads()`。

`input::reset(input)`：

```cpp
取消 key_press_repeat_id 任务；
取消鼠标左键延迟任务；
task_pool.push(reset_input_state, input);   // 在任务池线程上执行，与注入串行
```

**真正销毁设备**走 `input::terminate_gamepads()`（全清）或 `input::terminate_gamepads(session_id)`（按身份清）：在锁下 swap 出保留表条目，再在任务线程上销毁。

## 10. 小结

| 关注点 | 结论 |
|--------|------|
| 输入包的可靠性 | 走 **ENet 可靠通道**（控制协议），不需自己重传 |
| 安全校验 | `validate_input_packet` 在入队前完成；畸形包丢弃并记日志 |
| 性能 | 1 线程 `task_pool` 串行注入 + 相对鼠标位移批处理 + 16 位溢出保护 |
| 状态一致性 | `key_press` / `mouse_press` / `modifier_state` / `back_button_state` 四组状态，断开时统一复位 |
| 暂停-恢复 | 保留输入上下文（`retained_input_map_t`），手柄设备不重建 |
| 反向通道 | 手柄力反馈经 `feedback_queue` → `send_feedback_msg` → 6 种控制消息 |
